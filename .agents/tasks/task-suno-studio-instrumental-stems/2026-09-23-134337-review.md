# Seven stem-targeted Suno Studio instrumental plugins (v1)

Adds seven post-render Suno Studio audio-effect plugins for the instrumental / non-lead-vocal stems (bass, keys, guitar, strings, synth, backing vocals, FX/other), each in its own `plugins/<name>/<name>.plugin.json`, alongside doc updates (`plugins/README.md`, `plugins/AUTHORING.md`, `CHANGELOG.md`, top-level `README.md`). The batch extends the six existing vocal plugins with the same structural template: `effect` kind, stereo `audioIn`->`audioOut`, a per-channel `chain(x)` closure, input/output gain, bypass toggle, dry/wet mix, a signal-chain header comment, and a terminal `g.tanh` safety stage. The two degrade-oriented plugins (synth, texture) reuse the digital-degrade fixed 8-level amplitude quantizer verbatim rather than inventing a new technique, and backing-vocal-tucker is honestly documented as a static (non-sidechained) tuck. All seven ship UNVERIFIED, which is the intended and correctly labeled status.

Watch for: the `warm-keys-voicer` attack-soften stage per-sample gain-modulates the full-band signal by an envelope ratio, which is amplitude modulation and can distort sustained tones, not just round transients (likely). Everything else is internally consistent with `AUTHORING.md` and the existing six.

**Verdict**: APPROVED

## High-level view

The DSP chains are coherent and each names its target stem in both `description` and the code header, keeping the post-render / not-a-lyric-tag framing intact. Filter modes, the `gainDb` shelf/peaking assumption, the `g.lerp(mix, dry, processed)` order, the `g.lerp(bypass, out, trimmed)` selection, and the one-pole coefficient approximation are all applied exactly as the existing six plugins and `AUTHORING.md` prescribe.

The quantizer reuse is genuine: the `staircase` function in `synth-cold-glitch` and `texture-filter-degrade` is byte-for-byte identical to `digital-degrade` (same hash), blended by their `quantize` / `degrade` knobs. No new degrade technique was invented, and no unconfirmed primitive appears anywhere in the seven.

The only design smell is `warm-keys-voicer`'s attack-soften: it divides a lagging envelope by the instantaneous level and multiplies the signal by that ratio, which is a per-sample amplitude modulation rather than a transient shaper. It is bounded (clamped to [0,1]) and blended by a percent, so it will not blow up, but it is the one stage whose audible result is least predictable and most deserving of a listen-test.

Docs are accurate: the per-stem intro, the Layout block, the use-case table, and the Tier 1 list of 13 all match the seven shipped plugins and their stems. Parameter / control / UI-box triples agree in every file (8/8/8 for six plugins, 9/9/9 for backing-vocal-tucker). No em dashes were introduced in authored content.

### Quantizer reuse is verbatim, not a re-implementation

The task requires synth and texture to reuse the sanctioned digital-degrade quantizer, not invent a degrade. They do: the `staircase(x)` closure (clamp to [-1,1], sum of seven `g.compareLt` comparators at fixed thresholds, map the 0..7 index to the center of one of eight levels) is identical across `digital-degrade`, `synth-cold-glitch`, and `texture-filter-degrade` down to the byte (same md5). Each new plugin blends it in with its own knob (`quantize`, `degrade`) via `g.lerp(qMix, band, quantized)`, exactly mirroring digital-degrade's `crush` blend. The header comments in both new plugins state the reuse and repeat the fixed-depth limitation honestly rather than implying a variable bit crusher.

One caveat carried over from the source: `synth-cold-glitch` runs the staircase on `band`, the output of a highpass/lowpass pair whose amplitude can sit well below unit scale. The staircase thresholds are fixed across [-1, 1], so a quiet band lands in only the innermost levels and the effective quantization is coarse relative to the signal. This is the same behavior digital-degrade has (it quantizes post-drive, which at least pushes toward the rails), and it is acceptable for a glitch texture, but the grit character will depend heavily on level going in.

### warm-keys-voicer attack-soften modulates the whole band

The soften stage builds `env` from `g.asymmetricOnePole` over `g.abs(trimmed)` (slow 30ms attack, fast 8ms release), takes `inst = max(abs(trimmed), 1e-6)`, forms `softGain = clamp(env/inst, 0, 1)`, and blends `trimmed` toward `g.mul(trimmed, softGain)` by the `soften` percent. Because a slow-attack envelope lags a rising transient, `env/inst` dips below 1 at onsets and pulls the peak down, which is the intended transient rounding. The concern is that this ratio is applied to the full-band signal every sample, so it is a time-varying gain (amplitude modulation) rather than a band-limited transient shaper. On sustained material where `env` and `inst` diverge (vibrato, tremolo, decaying tails), the moving gain can add sidebands / roughness that read as distortion rather than softening. It is bounded and percent-blended so it degrades gracefully, but it is the one stage in the batch whose audible outcome is hard to predict from the graph, and it should be listen-tested before relying on it.

### backing-vocal-tucker tuck is honestly static

The tuck is `tuckLin = g.dbToLin(-tuck)` multiplied into the signal: a fixed attenuation, not a lead-driven sidechain duck. That is the only option here (no sidechain / lead input exists for these effects), and both the control description ("not a sidechain duck") and the code header ("STATIC gain reduction ... does not respond dynamically to the lead's level") say so plainly. The description matches what the graph does.

### sub-tightener boom-tamer scales with level, not dB

`sub-tightener` isolates a low band with a lowpass, tracks its envelope, and attenuates by `env * tighten` (clamped to [0,1]) before recombining with the rest. The soft spot is that the linear-amplitude envelope means the tame amount scales with raw level rather than following a dB curve, so the same `tighten` setting bites harder on hotter passages. The tilt shelves and envelope-coefficient math otherwise follow the existing six exactly (`gainDb: tiltDb` / `gainDb: negTilt` opposed shelves, `coef = clamp(1 - 1/(seconds*sr), 0, 0.9999)`), with the `gainDb` assumption flagged in each header.

`plugins/README.md` gains a per-stem intro note, a Layout block listing all thirteen files with one-phrase descriptions, seven new use-case table rows keyed to the correct stems, and a Tier 1 list that now enumerates thirteen (six vocal, seven stem-targeted).
