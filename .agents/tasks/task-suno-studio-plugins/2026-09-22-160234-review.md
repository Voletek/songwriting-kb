## High-level view

Issue #1/#4 is genuinely fixed. The new `staircase` clamps to [-1,1], counts how many of seven fixed thresholds (-0.75..0.75) the sample exceeds, and maps that 0..7 index to the center of one of eight levels. Numerically it collapses distinct inputs to the same output (0.05 and 0.20 both map to +0.125) while keeping nearby inputs distinct (-0.30 to -0.375, -0.10 to -0.125), so it is real quantization, not the identity. The dead `2^crush` comment, `half`, and `invLevels` are removed; `crush` now drives a clean/quantized blend, and the header, README, and CHANGELOG all describe an 8-level quantizer rather than a bitcrusher.

Issues #2, #3, #5 fall under the same theme: mechanics that v1 said were used but not documented are now written down as assumptions. AUTHORING.md gained an "Assumptions not yet confirmed" section covering the `g.lerp(mask, a, b)` argument order, the bypass enum resolving to a 0/1 mask, the shelf/peaking `gainDb` field, and the mono-port-to-L/R expansion. Each affected plugin header now carries a matching inline ASSUMPTION note pointing back to AUTHORING.md, so the code and the reference agree instead of the code silently depending on undocumented behavior.

Issues #6 (de-esser hard gate) is documented as a known limitation in both the de-esser header and a new "Known DSP limitations" section in AUTHORING.md, framed honestly as a zipper-artifact risk that would need an unconfirmed exp/log primitive to smooth. Since none of these four can be verified without running in Suno, documenting them truthfully is the appropriate resolution, and the change does exactly that.

The plugins remain valid JSON, use only whitelisted primitives, carry no em dashes in authored content, and touch no methodology, agent, SOP, skill, hook, or song files.

## digital-degrade quantizer is genuinely non-identity (Issue #1/#4, resolved)

The v1 no-op is gone. The new `staircase(x)` clamps `x` to [-1,1], then sums seven `g.compareLt` comparators at thresholds -0.75, -0.5, -0.25, 0, 0.25, 0.5, 0.75 to produce an index in 0..7, and maps that index to `-1 + (idx + 0.5) * 0.25`, the center of one of eight bands. Tracing the arithmetic confirms distinct inputs in the same band collapse to one output while inputs in different bands stay distinct:

```
0.05 -> +0.125    0.20 -> +0.125     (collapse: same band)
-0.30 -> -0.375   -0.10 -> -0.125    (distinct: different bands)
0.50 -> +0.375    0.51 -> +0.625     (threshold boundary)
-1.0 -> -0.875     1.0 -> +0.875     (endpoints)
```

This is real amplitude quantization built entirely from confirmed primitives. `crush` now sets `qMix = clamp((16 - crush) / 14, 0, 1)` and `g.lerp(qMix, driven, quantized)` blends clean toward quantized (crush=2 fully quantized, crush=16 clean), which matches the knob description. The dead `half`, `invLevels`, and the `levels = 2^crush` comment that v1 called out are removed, and the header now describes a fixed 8-level quantizer without any variable-bit-depth claim. The plugin `description`, metadata, `plugins/README.md` tree and use-case table, and CHANGELOG all say "8-level amplitude quantizer" instead of "bitcrush," so the naming is consistent end to end.

## Reverse-engineered reliances now documented as assumptions (Issues #2, #3, #5, resolved)

AUTHORING.md gained an "Assumptions not yet confirmed from the single example" section that states outright these items are consistent with observed primitive behavior but not confirmed and must be verified in Suno. It covers the `g.lerp(mask, a, b)` order (returns `a` at mask=0, `b` at mask=1), the bypass enum resolving to `"off"`->0 / `"on"`->1 so that off passes processed and on passes dry, the shelf/peaking `gainDb` field that the confirmed `g.biquad({ input, cutoff, resonance, mode })` signature does not list, and the mono `audioIn`/`audioOut` ports expanding to `...L`/`...R` rails. The section also notes there is no string primitive to map the enum in code, which is why it can only be a documented assumption rather than an explicit mapping, and that the port convention is consistent across all six plugins so it is right everywhere or wrong everywhere.

The inline headers now match. Every plugin's bypass line carries the enum-as-0/1 and lerp-order assumption; the three shelf/peaking plugins (`intimate-proximity`, `vintage-lofi-voicer`, `vocal-drive-edge`) additionally carry the `gainDb` assumption note. The code and the reference no longer disagree, which was the substance of the v1 concern: the reliance is now surfaced rather than silent.

## De-esser hard gate documented as a limitation (Issue #6, resolved)

The de-esser still ducks via a binary `g.compareLt(threshLin, env)` mask with no soft knee, but both the plugin header and a new "Known DSP limitations" section in AUTHORING.md now name the zipper-artifact risk and explain that a smooth gain computer would need an exp/log primitive outside the confirmed set. This is the honest characterization v1 asked for; the behavior is unchanged but no longer undisclosed.
