# Song-planner package + guided/collaborative writing mode (v1)

Adds a first-class planning stage to a Markdown songwriting toolkit and a third interaction mode to the songwriter agent, both unified under one "Collaborative / Guided Mode" concept. The planning half is a full package — a canonical methodology (`song-planning.md`), a thin agent, SOP 09, a 12-section Song Brief spec/template, and a sample brief — that turns SOP 01's inline "Phase 1: Analysis" into an approvable, on-disk `SONGNAME.brief.md` artifact produced before any lyrics. The writing half adds a section-by-section co-writing loop to `songwriter.md` that proposes a draft, self-flags it against the critic's 12-category rubric, and waits for user confirmation, plus a seam that consumes an existing brief instead of re-planning. The design intent — and the thing most worth checking — is that the guided modes are a new *interaction posture* over the *existing* methodology and critique rubric, with zero craft-logic duplication.

Watch for: a section-emphasis mapping in `songwriter.md` that stops at Final Chorus while the loop it documents walks two more sections (Intro/Outro) — a completeness gap, not a correctness bug (confirmed). Nothing here blocks shipping; the single-source-of-truth constraint holds throughout.

**Verdict**: APPROVED

## High-level view

The single-source-of-truth constraint is honored cleanly. `song-planning.md` describes a *procedure* and a *deliverable* and pulls every craft rule (prosody thresholds, hook timing, Fabbri, 70/30, key/BPM-emotion, Hit Formula F1/F2, V6 mode label, the 12 categories) in by reference to `songwriting.md` / `critique.md` / `SONGWRITING_KNOWLEDGE_BASE.md` / the `references/` files. No scoring scale, numeric threshold, or rubric definition is restated in any of the four new files or the two agents — grep confirms it. All nine `#[[file:]]` includes across the two touched agents resolve to real files on disk.

The shared "suggest a methodology-backed default → surface concerns → user confirms/overrides → next" loop is genuinely coherent across both sides: the planner applies it per brief-decision, the writer applies it per lyric-section, and both name it as the same concept with cross-references pointing at each other. The writer's per-section self-flagging correctly references `critique.md`'s categories by number/name (Hook 1, Prosody 3, Originality 6, Singability 7, Arc 4, etc.), and those numbers match the canonical rubric exactly.

The 12 brief sections appear in the required order in all three places they're defined (spec, SOP template, sample brief), and the sample brief stays conceptual — no verse lyrics, a candidate hook line flagged explicitly as a target phrase. Docs are consistent with on-disk reality: 7 method files, 6 agents, 9 SOPs all verified against the filesystem, and the README/CHANGELOG/WORKFLOW updates reflect the new stage and seam.

The one rough edge is a documentation completeness gap in the writer's section-emphasis table, which lists six sections while the loop above it walks seven. It's an omission of guidance for Intro/Outro, not an incorrect rule.

### Single source of truth: reference, don't restate

This is the constraint the change was built around, and it holds. `song-planning.md` opens by declaring itself canonical for the *planning procedure and deliverable* and states plainly that it does not restate craft definitions. The body backs that up: every place a craft rule could have leaked in, it points elsewhere instead — Fabbri's 5 rules and the 70/30 split cite `songwriting.md` Step 7; hook timing (5-30s) cites Step 8; key/BPM-emotion cite `SONGWRITING_KNOWLEDGE_BASE.md`; the V6 mode label cites `references/V6_TAG_DISCOVERY.md`; the 12-category rubric cites `critique.md`. A "Decision Frameworks the Plan Draws On" table makes the pointer discipline explicit, mapping each framework to the brief section it feeds and the canonical file it lives in.

The grep evidence is clean: none of the four new files nor the two edited agents contain a rubric scoring scale (`9-10 / 7-8 / … / 1-2`) or a redefined threshold. The single incidental `3-4` match in `songwriter.md` is a pre-existing render-count line, not a scoring scale. The agents carry no craft logic — `song-planner.md` is frontmatter + behavioral directives + four includes (`tenets.md`, `song-planning.md`, `songwriting.md`, `critique.md`), and even instructs itself to "contain NO craft rule definitions in your own reasoning."

### The guided loop is one concept applied twice

```
        PLANNER (per brief decision)          WRITER (per lyric section)
        suggest default ──┐                   propose draft ──┐
        surface concerns  │  same loop        self-flag vs    │  same loop
        user confirms  ───┤                   critique.md  ───┤
        next decision ────┘                   next section ───┘
                 └──── [Song Brief] ──feeds──▶ seeded draft ──┘
```

Both halves name the loop identically and cross-reference each other. The PLAN→WRITE seam is concrete: the writer checks for a `SONGNAME.brief.md` next to `SONGNAME.md`, treats its 12 sections as completed Phase 1 analysis, and skips inline planning when present; if absent it plans inline or defers to the planner. One subtlety worth noting — the old "Execution Rules (Both Modes)" heading was rescoped to "(INTERACTIVE & AUTO-PILOT modes)"; without that edit the "write the complete song in one pass" rule would have directly contradicted the new pause-after-each-section behavior.

### Per-section critic checks reference the real rubric

The writer's self-flagging step references `critique.md`'s categories by number, and they match the canonical file exactly (Hook 1, Prosody 3, Arc 4, Structure 5, Originality 6, Singability 7, Emotional Intelligence 12). A1-A5 stay available for a full pass rather than folded into the per-section loop, and critic/suno-optimizer are left unchanged.

The gap is completeness, not correctness. The documented Nashville-order walk is:

```
Chorus → Pre-Chorus → Verse 1 → Verse 2 → Bridge/the Turn → Final Chorus → Intro/Outro
```

but the emphasis mapping table has rows only through Final Chorus. Intro/Outro gets walked with no first-surface guidance. Because the text says the full 12 checks always apply regardless of section, behavior is still defined — but a reader stepping through Intro/Outro gets no steer on what matters there. A one-line row (or an explicit "full rubric, no subset" note) closes it.

### Sample brief stays conceptual

The 12 sections appear in the required order across the spec, the SOP 09 skeleton, and the filled sample. The sample matters because it's the one place verses could have leaked in — and grep finds no `[Verse]`/`[Chorus]`/`[Bridge]` tags or lyric lines; section 10's candidate hook line is explicitly annotated "target phrase only — not finished chorus lyrics." It sits next to the existing `Three_In_The_Morning.md`, demonstrating the `SONGNAME.brief.md` convention in place.

### Docs and counts

Filesystem check confirms 7 method files, 6 agents, 9 SOPs — matching the README counts, the Agents table (six roles), the SOP 09 row, and the CHANGELOG/WORKFLOW updates. `SONGWRITING_KNOWLEDGE_BASE.md` was correctly left untouched — it's a pure craft reference that doesn't enumerate agents/SOPs/pipeline.

One durability caveat: the guided walkthrough is documented in two places (SOP 09 / `songwriter.md`) and the section-emphasis mapping is duplicated in a third (SOP 01 Phase 2). Nothing checks these stay in sync, so an edit to one can silently drift from the others — the Verse-2 label divergence between the agent table and the SOP 01 note is an early instance.
